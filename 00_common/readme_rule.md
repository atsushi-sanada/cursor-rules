# README 作成ルール

エディタ/IDE での README 作成における共通ルール。README は入口説明書として「概要」と「最低限の使い方」に特化し、細かい仕様はコードコメントへ逃がす構成にします。

---

## 基本方針

- **入口説明書としての役割**：プロジェクトの概要と最短で使えるまでの情報に特化
- **簡潔性**：長くなりすぎず、更新しやすい構成を維持
- **詳細はコードへ**：細かい仕様やロジックはコード内のドキュメンテーションを参照

---

## README テンプレート

```markdown
# プロジェクト名

<!-- 例：ガチャ分析ツール / シミュレーション自動化スクリプト -->

## 概要

<!-- プロジェクトの目的・何ができるかを2〜4行で簡潔に説明 -->

---

## セットアップ

<!-- "最短で使えるまで" に必要なステップだけを書く。細かい説明は不要 -->

---

## 使い方

<!-- 「どう動かすか」ではなく「どう使うと目的が達成できるか」を中心に -->

---

## その他

<!-- READMEが複雑にならないよう、補足情報はここに最低限まとめる -->
<!-- TIPSやオプションなど -->

### その他の詳細について

- 個別の仕様や詳細なロジックは、**プロジェクト内の各コードのドキュメンテーションを参照**してください
- README はあくまで「最短で触れるための入口」です
```

---

## 構成の考え方

### この 4 項目だけで十分な理由

1. **新人が知りたいのは「何のプロジェクトか」が中心**

   - 概要があれば目的が明確になる

2. **技術詳細はコードに記述したほうが最新状態に保ちやすい**

   - README に詳細を書くと更新漏れが発生しやすい

3. **README が長くなると更新されず役に立たない**

   - 簡潔に保つことでメンテナンス性が向上

4. **最低限「概要・セットアップ・使い方」さえあれば、誰でも触れる**
   - 入口としての役割を果たせる

---

## 必須セクション

以下の 4 セクションを必ず含める：

1. **概要**：プロジェクトの目的と機能を 2〜4 行で簡潔に説明
2. **セットアップ**：最短で使えるまでの手順（3〜5 ステップ）
3. **使い方**：目的達成のための基本的な使い方
4. **その他**：TIPS、オプション、詳細情報への参照

---

## 記述ルール

### 概要セクション

- **2〜4 行で簡潔に**：長文は避ける
- **目的と機能を明確に**：何ができるかを最初に示す
- **ターゲット読者を意識**：誰が使うツールかを示す

### セットアップセクション

- **前提条件を明記**：必要なツール・環境を最初に示す
- **手順は 3〜5 ステップに収める**：多すぎると読者が離脱する
- **コマンドはコードブロックで記載**：コピペしやすくする
- **詳細はコードへ逃がす**：設定の詳細はコード内コメントを参照

### 使い方セクション

- **目的達成の流れを中心に**：技術的な操作手順より、どう使うと目的が達成できるかを重視
- **ステップバイステップで記載**：番号付きリストで明確に
- **具体例を含める**：抽象的な説明より具体例が理解しやすい

### その他セクション

- **TIPS**：よくある問題と解決方法
- **オプション**：開発モードやテスト実行など
- **詳細情報への参照**：コード内ドキュメンテーションへの誘導

- [ ] 前提条件（必要なツール・環境）が明記されているか
- [ ] 使い方が目的達成の流れで書かれているか
- [ ] コマンドがコードブロックで記載されているか
- [ ] 詳細な仕様がコード内コメントへ逃がされているか
- [ ] README が長すぎず、更新しやすい構成になっているか
- [ ] Markdown 記法ルールに準拠しているか（見出し階層、コードブロックなど）
