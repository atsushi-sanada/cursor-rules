# README 作成ルール（AI向け）

## 1. 役割

- README は**入口説明書**。目的・構成・使い始める手順だけを書く
- 詳細仕様・例外・内部ロジックは README に書かず、コードまたは専用ドキュメントへ置く
- **1画面で読み切れる**量にする

## 2. 必須セクション

`# タイトル` の直後に目的（箇条書き）を書き、その後は **次のどちらか** の見出し構成にする。

### パターンA（手順を分ける）

```
構成
セットアップ
使い方
その他
```

### パターンB（手順を1本化）

```
構成
基本フロー
その他
```

- 作業が一直線（初回から完了まで途切れない）なら **パターンB** を選ぶ
- パターンB の `## 基本フロー` は番号付き手順のみ。最大6ステップ
- `## 概要` は設けない
- セクション間に `---` は入れない

## 3. 書き方

### 全体の流れ

| 順 | 内容 | 置き場所 |
| --- | --- | --- |
| 1 | 目的と成果 | `# タイトル` 直下の箇条書き（2〜4項目） |
| 2 | 構成（置き場所） | `## 構成` |
| 3 | 手順 | パターンA: `セットアップ` + `使い方` / パターンB: `基本フロー` |

- 手段だけを先に書かない
- タイトル直下の目的は箇条書きにする（1項目1文）
- 構成は箇条書きまたは表、手順は番号付きリストに分ける
- 手順セクションに背景説明や仕様説明を入れない
- 手順の先頭に clone や環境準備だけのステップを置かない（フロー本体から書く）

### セクション別

| セクション | 書くこと | 制限 |
| --- | --- | --- |
| （タイトル直下） | 何のプロジェクトか、何ができるか | 箇条書き2〜4項目。1項目1文 |
| 構成 | 主要フォルダ・ファイルの役割 | 1項目1行。見出しは `## 構成` |
| セットアップ | 初回手順（パターンA） | 番号付きのみ。最大5 |
| 使い方 | 更新・配布・日常運用（パターンA） | 初回手順と重ねない |
| 基本フロー | 初回から完了までの手順（パターンB） | 番号付きのみ。最大6 |
| その他 | 用語の最小定義、詳細ドキュメントへの誘導 | 最小限。膨らんだら削る |

### 書かないもの

- 手順の前提としての clone・Cursor 起動などの重複記載（例: 手順1が clone のみ）
- 手順1の前に前提条件の箇条書きを置く
- 運用の細かい制約（例: 大容量ファイルの Git 管理方針）→ 専用 README や runbook へ
- `### このプロジェクトについて` など、中身が分からない見出し
- セクション間の `---`

## 4. テンプレート

### パターンA

```markdown
# プロジェクト名

- 何のプロジェクトか（1文）
- 読了後に何ができるか（1文）

## 構成

- パス — 役割（1項目1行）

## セットアップ

1. 手順
2. 手順

## 使い方

1. 手順
2. 手順

## その他

- 詳細は各ドキュメント参照
```

### パターンB

```markdown
# プロジェクト名

- 何のプロジェクトか（1文）
- 読了後に何ができるか（1文）

## 構成

- パス — 役割（1項目1行）

## 基本フロー

1. 手順
2. 手順

## その他

- 詳細は各ドキュメント参照
```

## 5. 禁止事項

- 仕様・例外処理・内部ロジックを README に書く
- 同じ注意を複数セクションで繰り返す
- 手段だけ先に書き、目的が後から出る構成
- 1画面を超える長さ
- パターンA と パターンB の手順見出しを混在させる
- セクション間の `---`

## 6. 完成前チェック

- タイトルと直下の箇条書きだけで、何のプロジェクトか分かる
- `## 構成` で置き場所が一覧できる
- 手順が一直線なら `基本フロー` 1本、分かれるなら `セットアップ` と `使い方` に分かれている
- 手順の先頭が clone 前提だけになっていない
- 事実（構成）と手順が分離されている
- 手順がコピペで実行できる
- `---` が入っていない

すべて満たさなければ書き直す。
