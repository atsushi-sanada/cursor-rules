# README 作成ルール（AI向け）

## 1. READMEの役割

* READMEは**入口説明書**
* 書くのは「概要」と「使い始める手順」だけ
* **詳細仕様・例外・ロジックは禁止**（コードへ書く）

---

## 2. 必須セクション（順番固定）

```
概要
セットアップ
使い方
その他
```

※ この4つ以外は書かない

---

## 3. 文章の構成（判断整理の型）

README は、読者が**何のための文書か → 何があるか → 何をすればよいか**の順で理解できるように書く。
相談回答と同じく、**目的を先に置き、事実と手順を分け、次の行動まで落とす**構成を使う。

### 3.1 目的 → 状態 → 手段

手順の前に、読者が迷わないための3層を `概要` で先に示す。

| 層 | README で書く内容 | 置き場所 |
| --- | --- | --- |
| 目的 | 何のためのリポジトリか、何を解決するか | `概要` 先頭2〜4行 |
| 状態 | 読了後に読者が何を判断・実行できるか | `概要` 先頭2〜4行 |
| 手段 | 初回の始め方、更新・配布のやり方 | `セットアップ` / `使い方` |

手段だけを先に書かない。読者が「なぜこの手順か」を `概要` だけで追えるようにする。

### 3.2 結論 → 事実 → 次の行動

各セクション内でも、次の順序を守る。

1. **結論**: そのセクションで読者が得る答えを先に書く（例: このリポジトリはルール配布用）
2. **事実**: 置き場所、ファイル、連携、制約を箇条書きまたは表で列挙する
3. **次の行動**: 番号付きリストで、読者が次に取る操作を書く

`概要` は結論と事実、`セットアップ` と `使い方` は次の行動を担う。

### 3.3 事実と手順の分離

* **事実**（何があるか、どこにあるか、何ができないか）→ 箇条書きまたは表
* **手順**（何をするか）→ 番号付きリスト
* 1段落に事実と手順を混在させない
* 手順セクションに仕様説明や背景説明を入れない

### 3.4 経路が複数あるとき

読者の選択肢は表で比較し、1画面で選べるようにする。

* `概要` 配下に `### 適用方法`（または同等の見出し）を置く
* 表の列は **方法 / 用途 / 操作** を基本とする
* 運用上いちばん影響が大きい制約（手動コピー必須、同期なしなど）は、表の直後に**1行だけ**書く
* 同じ制約を別セクションで繰り返さない

### 3.5 優先順位と具体性

* `セットアップ` は初回に必要な操作だけ。最大5ステップ
* `使い方` は更新・配布・日常運用。初回手順と役割を重ねない
* 各手順は「いつ・どこで・何をするか」が分かる動詞で書く
* 判断が分岐する場合は、表または手順内の分岐で示し、読者を先送りしない

### 3.6 書く前の自己確認

README 全体を書き終えたら、次を確認する。

1. `概要` だけで目的と読了後の状態が分かるか
2. 事実（構成・制約）と手順が分離されているか
3. 複数経路がある場合、表で選べるか
4. いちばん重要な制約を1か所に集約しているか
5. `セットアップ` と `使い方` のどちらを読めばよいか明確か

## 4. READMEテンプレート

```markdown
# プロジェクト名

## 概要

目的と成果を2〜4行で書く。

### このリポジトリについて

- 構成・置き場所（事実を1項目1行）

### 適用方法

| 方法 | 用途 | 操作 |
| --- | --- | --- |
| 方法A | 用途 | 操作 |

制約や注意は表の直後に1行。

---

## セットアップ

- 前提条件

1. 手順
2. 手順

---

## 使い方

1. 手順
2. 手順
3. 手順

---

## その他

- 用語の最小定義
- 詳細ドキュメントへの誘導
```

---

## 5. セクション別ルール（最低限）

### 概要

* 2〜4行厳守
* 目的と成果を書く
* 抽象表現禁止

### セットアップ

* 前提条件を書く
* 手順は最大5ステップ
* 説明文は禁止
* 初回利用に必要な操作（clone、配置、確認など）はここに書く

### 使い方

* 更新・配布・日常運用の手順
* 番号付きリスト

### その他

* 最低限のみ
* 膨らみ始めたら削除対象

---

## 6. 禁止事項

* READMEに仕様を書く
* READMEに例外処理を書く
* READMEで全部説明しようとする
* READMEが1画面で読めなくなる構成
* 同じ制約や注意を複数セクションで繰り返す
* 手段だけを先に書き、目的が後から出てくる構成
* `クイックスタート` セクションを設ける

---

## 7. 最終チェック（Yes / No）

* 何のツールか一瞬で分かるか
* 利用経路が複数ある場合、表または同等の一覧で選べるか
* コピペで動かせるか
* 詳細はコードまたは各ドキュメントに逃げているか
* 目的・状態・手段の順が守られているか
* 事実と手順が分離されているか
* いちばん重要な制約が1か所にまとまっているか
* `クイックスタート` が含まれていないか

**Yes が揃わなければ書き直し。**
