# ファイル命名規則

## 命名の目的

- 誰が見てもファイル内容を即座に理解できること
- 検索性・並び順・再利用性を高めること
- バージョンや日付による履歴管理を容易にすること

---

## 結論（迷ったらこれ）

**使い分けは「どこで使う名前か（人が見るか／プログラムが読むか）」で決まります。**

- **コード内（クラス/関数/変数）**: `PascalCase` / `camelCase`
- **ファイル名（このドキュメントの原則）**: **英小文字＋`_`区切り（snake_case）**

### 優先順位（例外の扱い）

- **原則**：本書（`00_common/`）のルールに従う
- **優先**：言語/ツールごとの要件・規約がある場合は、該当する言語別ルール（`03_code/lang/`）を優先する

---

## 用語の補足（最小限）

- **PascalCase**: `UserProfile`
- **camelCase**: `userProfile`
- **snake_case**: `user_profile`
- **kebab-case**: `user-profile`

---

## 使い分け一覧（要点）

| 用途               | 推奨               | 補足                      |
| ------------------ | ------------------ | ------------------------- |
| クラス名           | `PascalCase`       | 型として目立たせる        |
| 関数・変数         | `camelCase`        | 多くの言語の標準          |
| 定数               | `UPPER_SNAKE_CASE` | 定数だと一目で分かる      |
| ファイル名（原則） | **snake_case**     | OS/CLI/ツールと相性が良い |
| URL                | **kebab-case**     | Web で一般的              |
| DB カラム          | `snake_case`       | SQL 文化と一致            |

---

## 命名基本ルール（ファイル名）

- **英語表記（半角英数字）を基本とする**
- **スペースは禁止。単語区切りは `_`（アンダースコア）を使用**
- **日付は `YYYY-MM-DD` 形式で末尾に付ける（必要な場合）**
- **用途・カテゴリ・バージョンなどをプレフィックスで明示する**
- **ファイル拡張子は自動で付与されるため省略しない**

### 例外（ツール/言語が要求する場合のみ）

- **Unity / C#**: ファイル名は基本的にクラス名と一致（`GameManager.cs`）
- **Python**: モジュール名は `snake_case.py` が標準（例: `game_utils.py`）

---

## ファイル名構成

```

\[カテゴリ]_\[内容]_\[バージョン]_\[日付].\[拡張子]

```

### 例

| 用途         | 命名例                                 |
| ------------ | -------------------------------------- |
| デザイン PSD | `design_top_kv_v2_2024-06-07.psd`      |
| 議事録       | `meeting_login_flow_2024-06-07.md`     |
| 仕様書 PDF   | `spec_user_auth_v1_2024-05.pdf`        |
| スクショ     | `screenshot_header_bug_2024-06-07.png` |
| バナー画像   | `banner_summer2024_kv.jpg`             |

---

## NG 命名例と理由

| NG 例                 | 理由                                |
| --------------------- | ----------------------------------- |
| `新しい画像.png`      | 内容が曖昧で検索できない            |
| `final.psd`           | どれが本当に final か分からなくなる |
| `コピー.psd`          | 意図が伝わらず、履歴管理できない    |
| `aaa.png` / `test.md` | 中身が不明・混乱の元になる          |
| `player score.png`    | スペースは事故源                    |
| `user-Profile.png`    | 大文字混在は差分/運用で混乱しやすい |
| `user-profile.png`    | `-` 区切りはこの命名規則では非推奨  |

## よく使うカテゴリ名一覧

| カテゴリ名    | 用途例                           |
| ------------- | -------------------------------- |
| `design_`     | デザインデータ（PSD / Figma）    |
| `spec_`       | 仕様書（PDF / Markdown）         |
| `meeting_`    | 議事録・会議メモ                 |
| `screenshot_` | UI やバグ報告用キャプチャ        |
| `banner_`     | プロモーション用画像             |
| `script_`     | 開発用スクリプト（sh / py など） |
